## Minimal transport addition

Use a versioned, typed nested payload under existing `GoldenRecord.source_fields`, provisionally `notice_source_v1`; this is an evidence-transport version, **not** ResearchSubject/Assess v3. Prefer one model/validator for this payload rather than adding many free-form positive flags. Proposed field names below are for the coordinator's patch; none exists by this proposal alone.

| Proposed field | Required contents and origin |
| --- | --- |
| `version`, `source_lane`, `notice_id` | Exact source identity (`sam.gov` plus original posting ID), not a title-derived ID. Check against GoldenRecord.record_id and original row/raw ID/URL. |
| `artifact_ref` | Original selected sweep/store snapshot locator, exact row locator, consumed artifact SHA256 and canonical row SHA256; keep byte hash and canonical-object hash distinct. Locator is data resolved within authorized roots, never an arbitrary path to open. |
| `native_ordinal` | Position in the original supplied census; separately retain native selected rank. It is diagnostic provenance, never a new relevance score. |
| `original_record` | Exact original row including raw payload. Do not synthesize SAM raw authority from a Golden display record. |
| `text_capture` | Original text fields and source paths, retained/full lengths and hashes, explicit truncation, complete extraction context/offset receipts where present. `source_depth_ref` points to the exact original native dossier depth rather than a synthesized `description_checked=true`. |
| `acquisition_ref` | Exact bound Assess EvidenceRef ID/record hash and source-depth origin. Optional typed SourceAcquisition may be transported for display, but the read context must recompute/check it from original depth. `last_seen`, ingest/query time and sweep generated time remain separate observations. |
| `family_context_ref` | Link to the captured full family census, with identity/version/hash; transport all supplied member snapshots or exact references to them. Serialized representative/suppression fields are explanatory output and must be recomputed. |

Missing nested payload is legal for old packs and non-notice lanes. It means **source-unbound notice diagnostics**, not a fallback to the old positive lexical qualifier. Do not rewrite legacy timestamps or immutable Assess/LeadRow IDs to populate it. Negative/raw/historical facts stay visible.

## One explicit read context, not ambient state

A small module such as `agents/golden_press/notice_bridge.py` should own four operations: (1) load/rebind a read context, (2) resolve a projected record to original source, (3) resolve full notice families, (4) calculate notice admission from the existing gates. These are proposed responsibilities, not new independently invented semantics.

The context is created once at the ordinary entry point, with explicit client, selected scope, root/review/state paths, selected sweep, current typed profile and taxonomy, original depth/review artifacts, full source census, reference clocks, and existing current Assess payload. It is passed as an explicit argument through `product_bundle._build_graph` -> `build_corrected_pack`/adapter -> qualification and through `capture_inputs`/`build_market_map`. No implicit production-root fallback. `product_bundle._build_graph` currently calls `notice_store.connect()` with no root; the bridge must receive the already-selected connection/snapshot or explicit root-local path, not introduce another global read.

Rebinding sequence:

1. Resolve the ordinary gate-designated input paths for the selected client/scope. Read one coherent snapshot and retain its consumed-byte hashes. Use `approval.current_assess_binding(..., sweep=actual_snapshot, profile=actual_profile)` / `binding.build_binding` and `binding_drift` for the canonical comparisons; explicit in-memory inputs avoid the stat-keyed binding memo. Preserve the existing observed-read integrity limits; hashes do not certify source truth or continuous immutability.
2. Load the current immutable Assess artifact through `load_current_assess_run` with the explicit state directory. Validate its schema/run identity and compare current scope/sweep/profile binding and `assess_projection_input_manifest` to the loaded original inputs. An exported envelope alone is insufficient: `export_current_assess_run` performs structural/identity validation but not the current-input comparison in `current_run_identity`/`strict_assess_run_for_release`.
3. Reuse/factor the existing read-only current-run and strict-release checks to accept explicit root/state paths and an explicit evaluation clock. Their accepted signatures currently lack a state-root override in these two wrappers. Do not copy their logic into the Golden classifier, call materialization/approval, or loosen the no-pointer result: absent, stale, invalid or schema1-history-only authority cannot authorize a new qualified graph row. Whole-report release permission is still separate from an individual notice's evidence/route decision.
4. Load and validate the actual taxonomy for this client from the selected root; bind exact bytes, client/version, aliases and provenance mappings, along with the typed capability profile. `evidence_route.build_context` currently reduces capability language to core/adjacent lists; that is insufficient for the accepted requirement engine. Missing taxonomy or an undisclosed derived taxonomy remains a named qualification gap. Do not silently derive permissive vocabulary to rescue a rejected source. The accepted Assess binding/projection manifest does not independently bind a taxonomy file: do not claim otherwise or silently rewrite its immutable identity. Bind taxonomy in the new graph context, and keep the existing approved profile and exact current requirement review as an upper bound; a wider taxonomy cannot independently enlarge approved qualification. Missing approval provenance remains a named gap.
5. Resolve each L1 row by exact lane+posting ID and coherent original revision. Check ID/URL/raw identity, source field bytes/hashes and any retained display field disagreements. Rebuild source passages and evidence roles from the original snapshot; ignore supplied registry/claim-authority flags. A store-only row can support bounded metadata/history even when no strict depth exists, but must not be dressed as a native depth receipt.
6. Recheck the pointer/input identity at the end of construction. If it drifted, keep a diagnostic failure and withhold current recommendations; do not mix revisions. A replay context requires the original bound source bytes and explicit historical mode/cutoff, not permission to reuse an old qualified sidecar as current truth.

The context's serialized receipt should expose hashes, source locators, rule versions and gaps for review. Its positive result must be computed at the trusted reader on each run. A caller-supplied context dictionary, matching self-generated hash, saved Assess `classification`, `graph_contract_certified`, or saved registry does not independently authorize anything. The threat boundary remains the existing sanctioned source reader/Assess contract, with its disclosed finite source-authenticity limits.

## Full family identity, chronology and order

Reuse `triage._notice_thread_key`'s conservative identity contract, factored into a shared pure owner if necessary: **source lane + structured agency + explicit issuing office + full normalized solicitation identifier**. Normalize only established whitespace/case or independently evidenced agency identifiers. Never strip call/amendment suffixes, remove numeric tokens or use title similarity. Missing any required namespace falls back to exact posting identity and an unresolved-family reason. Conflicting source IDs/tuples never merge.

The existing Assess family ID is not automatically interchangeable: `ledger._family_basis:350` contains source/office/solicitation but no independent agency dimension. Preserve those immutable historical IDs as references; join through exact posting membership and check the stronger source tuple. If a saved parent spans incompatible agency tuples, hold the graph join rather than silently renaming or splitting that parent under the same identity. Any persistent Assess identity migration belongs to its contract owner, not this bridge.

Resolve the family over the **full available source census before positive text/date/type filtering and before display caps**. `l1_store.run_l1_from_store` currently excludes historical/negative/no-term rows before dedupe, and Market Map's `fetch_store_candidates` only returns shaping/title matches. Capture the original full sweep and, for matched store families, all exact-tuple siblings from the already retained local store snapshot, without capability/type/deadline restrictions. This is a bounded read of existing data, not Step7 collection or backfill. Where a complete sibling view is unavailable, say so; do not declare latest based on a positive-only subset.

Apply `temporal.latest_posting` to the original values, preserving its conservative handling of mixed precision, ties/conflicts and unsupported timestamps. A supported latest closed/no-term member suppresses an older positive; contacts, larger descriptions and “live” labels cannot override chronology. Unresolved order can choose an input-order display representative but cannot establish current-action authority. Do not substitute `ledger._posting_order` string sorting or a new maximum of unrelated modified/posted dates for the accepted temporal contract; if supported original modified timestamps require a change, treat it as a named owner-controlled rule amendment with explicit tests.

Return one family decision plus every original member/snapshot reference, original ordinal, source-field identity, temporal parse state, selected/superseded/unresolved status, reason and suppression edge. Recompute this from originals, not `triage_notice_lineage` supplied in a cached row. Preserve all available history and missing-history status; count repeated same-ID conflicting snapshots explicitly. A store revision counter is not a history array.

Family resolution does **not** invent ranking. Follow the caller's native input order for selected representatives (the accepted triage helper uses the representative's input ordinal); retain each original ordinal/rank. Remove graph hash/title/alphabetic sorting as a source of display priority. Keep L1's declared native screening rank as a separate producer decision; grouping must not add a second fit rerank. If a newer suppressing member is found outside the capped candidate set, retain it in family diagnostics and suppress the old recommendation; do not insert a replacement recommendation from outside the capture or fill the vacated slot. Version any intended native selection change prospectively, never rescore frozen cases.

## Cache and saved-output invalidation

`ExistingSystemsGraphAdapter.CLASSIFICATION_INPUT_FIELDS` currently excludes active/type, agency/office/solicitation, posted/modified clocks, original raw payload, source-depth and family membership. Add all newly read decision inputs, or preferably their **freshly recomputed** canonical dependency hashes, plus a versioned native admission/family policy. Bump `CLASSIFICATION_CACHE_VERSION` and `evidence_route.CLASSIFIER_VERSION`; update the adapter's decision overlay fields for distinct qualification/gap/provenance states.

The dependency fingerprint must include selected scope, exact taxonomy/profile/route/review bindings, original source and depth snapshots, acquisition authority, current read/presentation clock policy, and the full family census/representative decision. Adding a newer sibling must invalidate an older row's decision even when its own text is unchanged. A changed URL/identity/access source is decision material; it can no longer be omitted under the old “presentation only” exception. Plain display typography can remain outside the key.

Revalidate original sources before accepting a cache hit. Cache can save discovery/classification computation, but a cached positive must never replace current source rebind or review/action/route/clock gates. Cache metadata itself is not authority. Bind saved sidecars to their actual source/context digest and code/policy version; current readers recompute/verify rather than trusting the schema string. Preserve old sidecars for labeled historical replay and report stale/unavailable current state. No cache deletion or schema migration is needed for this design assignment.

## Minimal new acceptance cases (proposed, not executed)

1. **Transport round trip:** original sweep and store-shaped row -> GoldenRecord JSON -> graph -> Market Map preserve exact identity, text completeness, raw timestamps, source-depth refs and family members. An old pack with only match terms/display `retrieved_at` remains source-unbound. Verify separate agency/subtier and solicitation/notice IDs.
2. **Ordinary positive path:** original-source fixture with same-notice complete trusted depth, original aware acquisition, explicit requested work/current response instruction, recognized eligible route and current bound Assess review survives ordinary constructor -> resolver -> qualifier -> native action row. It does not automatically create a seller-ready child. Positive in-scope independent calls both survive.
3. **Independent gates:** mutate one positive source leg at a time (boilerplate/negation, missing depth, missing or stale acquisition, inactive/cancelled, expired/ambiguous deadline, absent instruction, unknown `8(a)`/code conflict, contact-only route). Each removes only unsupported qualification/action and retains explanatory diagnostics. Baseline regressions are reused, not rerun here.
4. **Original-source rebind:** forge saved `qualified`, `service_fit`, source registry/authority, family key, lineage, acquisition or matching self-generated hashes without original source change. No upgrade. Change original text under stable ID, swap source-depth posting ID or change profile/taxonomy/review; current state is invalidated. Direct helper/sidecar entry has no hidden legacy qualification fallback.
5. **Full family census:** renamed verified amendments collapse; same-title independent umbrella calls, different agencies/offices and missing namespace remain distinct. New closed/no-term/out-of-boundary sibling outside the positive slice suppresses old positive. Mixed precision/ties remain unresolved. Preserve all snapshot history, original ordinals and no replacement/backfill.
6. **Cache changes:** warmed positive, then only sibling/currentness/active/route/review/taxonomy/depth dependency changes. Cache cannot preserve qualification. Old version overlay and schema-only sidecar fail current admission; explicit historical rendering retains original bytes without implying freshness.
7. **Both consumer entrances:** normal complete bundle and direct Market Map/store/sidecar entrances use the same bridge; newly validated zero set stays zero even when legacy rows or forecasts exist. Reused ID cannot keep stale title/date/URL/action/targets. Eight slots, full parent assessment, Market Map context and target provenance remain.
8. **Contract preservation:** root-owned NETSCOUT representative URLs/history remain; old Assess/LeadRow IDs and schema1/2 history/anti-relabel rules stay intact. No-pointer, stale pointer, current input drift, missing source and approved partial report remain distinct. Prospective ResearchSubject v3 reader integration uses only the published root contract; no schema fields or implementation are guessed here.
