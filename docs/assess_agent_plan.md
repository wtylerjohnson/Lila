# Implementation Plan — The "Assess" Agent

**Goal:** ingest raw opportunity data, run it through Hybrid Fusion, score each
fused opportunity against a `CapabilityProfile`, and return a **ranked list of
high-match targets** — each one traceable, hygiene-checked, and gated for human review.

**Inputs:** `data/raw/*.json` (API pulls) + `data/raw/client_capability_profile.json`
**Output:** ranked `list[AssessmentResult]` written to `data/cleaned/assessments_<date>.json`
**Contract:** every type is defined in [`agents/schemas.py`](../agents/schemas.py).

---

## Architecture

```
RawOpportunity[]          (from tools/api — Discovery Trigger)
      │
      ▼  Phase 1: cheap pre-filter (NAICS / value / set-aside)  ── drops obvious non-matches
      │           BEFORE paying for browser enrichment
      ▼
candidate RawOpportunity[]
      │
      ▼  Phase 2: Hybrid Fusion  (tools/browser/enrichment_gate.fuse)
      │           retrieve doc -> semantic map -> reconcile -> synthesize
      ▼
FusedOpportunity[]  (+ Discrepancy logs)
      │
      ▼  Phase 3: scoring        (agents/assess/scoring.py)
      │           weighted MatchSignal[] -> match_score + why_this_match
      ▼
AssessmentResult[]
      │
      ▼  Phase 4: rank + Review Gate
      ▼
ranked high-match targets  ──►  TARGET engine
```

> **Why pre-filter before fusion?** The Contextual Enrichment Gate is the expensive
> step (browser automation + PDF parsing per opportunity). Phase 1 uses only free API
> metadata to discard records that can't possibly match (wrong NAICS, out of value band,
> ineligible set-aside), so we only pay for fusion on plausible candidates.

---

## Phase 1 — Pre-filter (`agents/assess/prefilter.py`)
Pure functions over `RawOpportunity`, no I/O. Drop a record if:
- none of its NAICS/PSC codes intersect the profile, **and**
- `estimated_value` is outside `[min_contract_value, max_contract_value]`, **or**
- it carries a set-aside the client is ineligible for.

Keep it **inclusive** — when in doubt, pass through to fusion. False negatives here
are silent lost deals; false positives just cost one enrichment pass.

## Phase 2 — Hybrid Fusion (orchestration only; logic lives in `tools/browser`)
For each surviving candidate, call `enrichment_gate.fuse(opp)`:
1. `retrieve_source_document` — Browser Tool locates + downloads the SOW/RFP/agency page.
2. `semantic_map` — map jargon → taxonomy (`rapidfuzz` against a controlled vocab file).
3. `reconcile` — diff API vs. document on amount / dates / scope / NAICS / set-aside.
4. synthesize `fused_summary` from both sources; populate `provenance`.

Any `BLOCKER` discrepancy → write to `data/discrepancy_logs/` and set
`requires_human_review=True`. **The opportunity is still assessed** (so the human sees
the score) but is flagged, never auto-promoted.

## Phase 3 — Scoring (`agents/assess/scoring.py`)
Compute one `MatchSignal` per dimension, each carrying its own **evidence string**
(this is what makes "Why This Match" defensible and traceable):

| Dimension      | Source of truth                              | Method                                    |
|----------------|----------------------------------------------|-------------------------------------------|
| `naics`        | code intersection                            | exact match = 1.0; adjacent family = 0.5  |
| `set_aside`    | profile eligibility vs. opp set-aside        | eligible-and-matched = 1.0                 |
| `tech`         | `tech_stack` vs. **document full text**      | fuzzy term coverage (`rapidfuzz`)         |
| `past_perf`    | `past_performance_keywords` + USAspending    | keyword hits + comparable prior awards    |
| `value_fit`    | `estimated_value` vs. profile band           | in-band = 1.0; near-edge tapers           |
| `agency_fit`   | `target_agencies`                            | listed agency = 1.0                       |

`match_score = Σ(signal.score × signal.weight) / Σ(weight)` — weights live in one
config dict (`SCORING_WEIGHTS`) so tuning is a single, reviewable change.

`why_this_match` is generated by concatenating the top-N signals' evidence strings —
**no free-form LLM prose without cited evidence behind it.** `traceability` is copied
from the `FusedOpportunity.provenance`.

## Phase 4 — Rank + Review Gate (`agents/assess/assess_agent.py`)
- Sort `AssessmentResult[]` by `match_score` desc.
- Apply `threshold` (default 0.6) to define "high-match."
- Partition output: `auto_review_ready` vs. `requires_human_review` (discrepancy-flagged).
- Persist to `data/cleaned/assessments_<date>.json`; emit a Markdown Review Gate summary.
- **Stop.** Promotion to the Target engine requires explicit human sign-off.

## File-by-file build order
1. `agents/schemas.py` ✅ (scaffolded) — freeze the contract first.
2. `agents/assess/prefilter.py` — pure, fully unit-testable, no network.
3. `agents/assess/scoring.py` + `SCORING_WEIGHTS` config.
4. `agents/assess/assess_agent.py` — wire prefilter → fuse → score → rank → gate.
5. `tools/browser/enrichment_gate.py` — real implementation (mockable behind an interface).
6. `tools/api/*` — real SAM.gov / USAspending clients.

## Testing strategy
- **Phases 1 & 3 are pure** → deterministic unit tests with fixture `RawOpportunity` /
  `FusedOpportunity` objects. No mocking needed. This is most of the win-logic.
- **Phase 2** → mock the Browser Tool + PDF parser; assert discrepancy detection and
  that no `RawOpportunity` ever escapes as a final result.
- **Golden test:** one fully-fused fixture with a known capability profile must produce
  a stable `match_score` and `why_this_match` — guards against silent scoring drift.

## Deferred / open decisions
- **Semantic taxonomy source** — controlled vocabulary file vs. embedding similarity.
  Recommend starting with a hand-curated YAML vocab (auditable, deterministic).
- **Win-probability model** lives in the **Target** engine, not Assess. Assess answers
  "can we do this work?"; Target answers "can we win it?". Keep them separate.
- **`SCORING_WEIGHTS` calibration** — seed with sensible defaults; tune against closed-won
  history once CRM data is wired in.
